# 业务员-客户沟通系统架构草案（基于 contract 项目）

## 1. 项目背景与目标
- 现有 `contract` 前端提供等额本息计算（`js/calculator.js`）与合同模版填充下载（`js/contract.js` + `doc/*.docx`），但缺少围绕业务员与客户沟通、提醒、触达的统一平台。
- 目标：在当前栈（原生 JS + Docx/XLSX 模版）基础上，打造 **业务员沟通作业台**，覆盖客户360信息、沟通任务、贷款记录、逾期管理、提醒触达（企微/短信/智能电话）与数据统计，提升客户临期响应与合同执行效率。
- 关键能力：客户画像实时展示、沟通轨迹记录、自动临期识别、跨渠道提醒编排、合同/文档联动。

## 2. 总体架构
| 层级 | 模块 | 说明 | 现有能力复用点 |
| --- | --- | --- | --- |
| 前端 Web | 业务员作业台、客户360卡片、沟通任务列表、提醒弹窗、统计看板 | 使用既有 UI 与 JS 模块，新增“沟通中心”标签或多页应用展示客户信息与提醒内容。 | `AppCalculator` 生成计划供展示；`AppContract` 触发合同下载。 |
| 应用服务 | 客户服务、贷款/计划服务、逾期服务、沟通编排服务、报表服务 | 统一封装客户数据、计划、逾期与提醒任务，负责状态流转与触达策略。 | 可用 Node/Nest 等 REST API；初期可 JSON/IndexedDB 模拟。 |
| 集成层 | 企微消息、短信平台、智能电话助手（待定）、Email/Push（可选） | 提供临期触达的渠道适配，支持模板配置、发送回执、失败重试。 | JS 通过 `fetch('/api/notify/...')` 调度；可先 mock 接口。 |
| 数据层 | 客户、贷款、还款计划、逾期、沟通历史、触达任务、统计快照等表 | 支撑沟通记录与提醒链路；增加渠道回执与任务状态字段。 | 还款计划仍由 `calculateRepaymentPlan` 结果入库。 |

## 3. 功能模块设计
### 3.1 客户360档案
- **数据要素**：客户编号、姓名/主体、证件、联系信息、家庭/企业资产、风险等级、关联担保人、最近一次沟通方式。
- **展示内容**：页面顶部“客户抬头卡”聚合头像/姓名/风险标签/负责人；右侧显示联系方式与快捷拨号/企微入口；下方提供“沟通时间轴”展示业务员、客户在企微/电话/短信的互动摘要及附件。
- **作用**：业务员在外勤或电话前即可快速了解客户背景、当前在贷情况与历史沟通，降低信息搜集成本。

### 3.2 贷款与还款计划区
- **数据要素**：贷款编号、产品、放款日、金额、期数、费率、总利息、担保方式、合同编号、计划详情。
- **展示内容**： 卡片化显示“当前贷款概览”（本金、余额、下一期金额/到期日），下方复用 `#repayment-table` 展示详细计划，并附“下载计划 / 导出 XLSX”按钮。
- **作用**：帮助业务员在沟通时明确客户即将到期的金额及权益，支撑临期提醒、协商方案；并一键生成合同包或计划附件发送客户。

### 3.3 逾期与风险提醒
- **对象**：逾期待偿记录（支持多次）及风险事件（例如额度占比异常）。
- **展示内容**：逾期列表按严重程度颜色标识，显示 DPD、逾期金额、当前处理人、最近一次触达结果；右侧提供“处理动作”按钮（企微催收、短信、电话、记录承诺）。
- **作用**：集中呈现风险客户，要求业务员按 SLA 完成触达并记录结果，为催收转法务提供依据。

### 3.4 沟通任务与提醒中心
- **数据要素**：临期提醒任务、渠道策略、发送状态、回执、失败原因。
- **展示内容**：任务列表按“今日待办 / 即将临期 / 已完成”分栏；每条任务展示客户、渠道（企微/短信/智能电话）、计划触达时间、对应期数、推荐话术；右侧显示“发送/重发/改约”操作，以及触达结果（例如企微已读、短信状态码、电话录音链接）。
- **作用**：让业务员在一个界面内完成临期提醒、记录对话、触发多渠道外呼，并对未完成任务保持追踪。

### 3.5 合同与文档中心
- **展示内容**：模板列表（`FILE_TEMPLATES`），默认份数、上次下载时间、适用场景；点击模板后展示字段映射预览，允许输入客户/贷款信息并触发 `AppContract` 生成文件；侧栏列出“发送记录”与“客户签收结果”。
- **作用**：沟通完成后快速产出合同或告知函，将下载与客户沟通闭环在统一平台，并可直接在企微或邮件中发送附件。

### 3.6 系统管理与配置
- **展示内容**：角色与权限矩阵、渠道参数（企微 AgentID、短信签名、智能电话账号）、提醒策略（临期阈值、重复频次）、模板默认份数（对接 `FILE_TEMPLATES.defaultCopies`）。
- **作用**：让管理员配置沟通策略与渠道凭证，保证触达合规、口径统一，同时便于追踪不同业务线的运营效果。

## 4. 数据模型（核心表）
| 表 | 说明 | 关键字段（示例） |
| --- | --- | --- |
| `customer` | 客户主档 | `id`、`name`、`type`(个人/企业)、`id_no`、`mobile`、`risk_level`、`address`、`created_at` |
| `loan` | 贷款主表 | `id`、`customer_id`、`loan_amount`、`term_months`、`total_interest`、`monthly_rate`、`start_date`、`end_date`、`product_code`、`status` |
| `repayment_schedule` | 还款计划 | `id`、`loan_id`、`period`、`due_date`、`monthly_payment`、`principal`、`interest`、`remaining_principal`、`actual_pay_date`、`actual_amount` |
| `overdue_case` | 逾期案件 | `id`、`loan_id`、`schedule_id`、`dpd`、`overdue_amount`、`penalty_interest`、`status`、`assignee` |
| `communication_task` | 临期/逾期沟通任务 | `id`、`customer_id`、`loan_id`、`schedule_id`、`channel`(wechat/sms/call)、`planned_time`、`status`、`assignee`、`script_id`、`result` |
| `channel_event` | 渠道发送回执 | `id`、`task_id`、`channel_message_id`、`status`、`delivered_at`、`read_at`、`fail_reason`、`payload`(JSON) |
| `document_log` | 文档下载记录 | `id`、`loan_id`、`template_id`、`operator`、`downloaded_at`、`copies` |
| `stat_snapshot` | 指标日快照 | `id`、`stat_date`、`metric_key`、`metric_value`、`extra`(JSON) |

> 还款计划数据可直接写入 `repayment_schedule`：`calculateRepaymentPlan()` 返回的 `schedule` 数组包含 `period/date/monthlyPayment/principal/interest/remainingPrincipal`，保存即可；同时依据 `due_date` 自动生成 `communication_task`，按渠道策略推送到相应触达服务。

## 5. 核心业务流程
### 5.1 贷款建档
1. 录入/选择客户 → 校验证件、自动带出历史。
2. 输入贷款要素（金额、期数、总利息等）→ 实时调用 `AppCalculator` 展示月供、总额、年化利率。
3. 保存贷款 → 存储 `loan` 与生成的 `repayment_schedule`。
4. 选择合同模板 → `AppContract` 拉取 Docx，填充 `{{customer_*}}`、`{{loan_*}}`、`{{schedule_block}}` 等占位符。

### 5.2 还款&逾期
1. 录入实际还款（手工或导入），更新 `repayment_schedule.actual_*`。
2. 系统比对 `actual_pay_date` vs `due_date`，若超过阈值生成/更新 `overdue_case`，计算 `dpd` 与罚息。
3. 催收人员在案件详情记录跟进，更新状态与下次提醒。

### 5.3 数据统计
1. 每日定时任务聚合余额、逾期、合同下载量，写入 `stat_snapshot`。
2. 前端看板调用报表接口，展示趋势与分布。

### 5.4 临期提醒与沟通闭环
1. 系统每日扫描未来 N 天（可配置）的 `repayment_schedule`，创建 `communication_task` 并按照优先级推送到业务员作业台。
2. 业务员可在任务列表直接点击“企微提醒”“发送短信”“预约智能电话”，系统将调用对应的集成服务完成触达。
3. 渠道回执（例如企微已读、短信发送成功、智能电话接通与录音链接）写入 `channel_event`，并实时展示在客户时间轴。
4. 若触达失败或客户未响应，系统按照策略自动切换下一个渠道（如企微失败 → 短信 → 智能电话），并提醒业务员补充人工跟进。
5. 沟通结果（客户反馈、承诺还款时间）记录在任务中，同时可触发合同/告知函生成并通过同一渠道发送附件，形成闭环。

## 6. 前端界面规划
- **Dashboard**：展示“今日需触达客户数”“即将到期金额”“企微/短信/电话成功率”卡片，搭配逾期热力图，帮助主管掌握沟通效率。
- **客户列表与360详情**：支持关键词、风险等级、负责人筛选；详情页包含抬头卡、沟通时间轴、快捷触达按钮以及“下一步动作”提示。
- **贷款/计划面板**：复用当前 `#repayment-table` 展示计划，增加“下一期信息条”与“临期提醒倒计时”，并可直接勾选计划条目创建沟通任务。
- **沟通任务中心**：Kanban 视图按状态拖拽任务；列表项显示渠道、计划触达时间、推荐话术、脚本；任务详情内嵌短信/企微模板编辑器及电话拨号器。
- **逾期中心**：按 DP D 阶段分组呈现案件，提供跟进记录、证据上传、法务移交按钮，并可过滤已触达渠道。
- **文档中心**：模板配置页 + 下载日志，支持一键将文档作为附件附带到企微/短信链接中。
- **设置**：渠道参数、提醒策略、模板默认份数、权限矩阵及业务字典维护。

## 7. 技术实现要点
- **前端栈**：延续当前无框架模式，按模块拆分 JS（`AppCustomer`, `AppLoan`, `AppReports`），或引入轻量框架（如 Vue）增强状态管理。
- **文档生成**：保留 `docx.umd.js` + `JSZip` 流程，新增字段映射表，支持多模板批量下载。
- **数据存储**：短期可用本地 JSON/mock，长期需要后端（Node/Express、NestJS 等）+ 数据库（MySQL/PostgreSQL）。
- **API 约定示例**：
  - `GET /api/customers?keywords=&risk_level=`
  - `POST /api/loans`（请求体含贷款要素 + 客户 ID）
  - `POST /api/loans/{id}/contracts/download`
  - `POST /api/communication-tasks/{id}/send`（body 指定渠道 wechat/sms/call）
  - `POST /api/integrations/wecom/callback`（接受已读/失败回执）
  - `GET /api/reports/summary?date=2025-01-01`
- **触达服务**：抽象 `NotifyService`，向企微/短信/智能电话适配器发送请求；可用消息队列或重试任务表保证可靠交付。
- **权限控制**：前端根据角色隐藏按钮，后端基于 JWT/Session 校验，并在敏感操作（下载合同、发短信）记录审计日志。

## 8. 外部触达集成
### 8.1 企业微信（企微）临期提醒
- **触发方式**：当 `communication_task.channel = 'wechat'` 且计划时间到达时，调用企业微信客服/群发 API，使用预置模板（含客户姓名、期数、金额、还款链接）。
- **展示内容**：任务详情内展示企微消息预览、模板变量说明、发送记录（时间、消息 ID、已读状态）；客户360时间轴同步展示“企微提醒已读/未读”。
- **作用**：利用客户与业务员既有的企微关系，提供高触达率的临期提醒；支持业务员实时查看客户是否已读并立即跟进。

### 8.2 短信平台临期提醒
- **触发方式**：`communication_task.channel = 'sms'` 或企微未读超过阈值自动补发短信；通过短信服务商 API（阿里云/腾讯云等）发送。
- **展示内容**：发送前可选择短信模板并看到字数、费用估算；发送后显示状态码（成功/失败）、运营商返回信息、短链点击次数。
- **作用**：覆盖无企微或企微未响应客户，保障提醒触达；短链可引导客户查看合同或在线还款。

### 8.3 智能电话助手临期外呼（平台待定）
- **触发方式**：当企微+短信无响应，或配置为高风险客户首选渠道时，调用智能电话助手平台 API（如公有云外呼平台），传入客户姓名、号码、话术脚本、预约时间。
- **展示内容**：任务面板显示预约外呼时间、脚本摘要、平台反馈的接通情况、通话录音链接；可一键标记客户反馈。
- **作用**：通过机器人或坐席外呼强化临期提醒，并沉淀录音供合规稽核；结合沟通任务 SLA 自动升级未接通客户。

> 三种渠道可通过策略引擎（优先级：企微 → 短信 → 智能电话）自动串联，也支持业务员手动切换；所有回执统一写入 `channel_event`，并在客户时间轴展示。

## 9. 数据统计指标定义
- **客户量**：累计客户、活跃客户（近 90 天有贷款）。
- **贷款余额**：∑ `remaining_principal`（未结清）。
- **逾期率**：`逾期余额 / 在贷余额`，可按 M0(1-30)、M1(31-60)、M3(>90) 细分。
- **沟通触达指标**：企微/短信/智能电话发送量、成功率、已读率、接通率、平均响应时间。
- **合同下载量**：`document_log` 按模板/用户统计。
- **收益指标**：已收利息 vs 计划利息差值。

## 10. 权限与安全
- 登录与会话：建议接入企业 SSO 或自建账号系统。
- 操作审计：客户、贷款、逾期、合同下载以及每一次触达任务发送/取消/重试均写审计日志。
- 数据脱敏：界面与导出对身份证、手机号做掩码显示；仅管理员可查看全量。
- 文件安全：合同下载需密码验证（已实现），可扩展一次性 token、二维码验证。
- 渠道安全：企微/短信/电话凭证单独加密存储，调用前做权限校验，防止误发。

## 11. 迭代路线（建议）
1. **MVP（当前基础增强）**：在现有页面增加客户/贷款表单、计划保存、本地存储+导出、合同下载日志。
2. **阶段二**：上线沟通任务中心，接入企微与短信渠道，完成回执闭环与提醒看板。
3. **阶段三**：集成智能电话助手、完善策略引擎与多渠道编排、权限体系、催收流程、移动端适配。

该设计以项目现有计算&合同核心为出发点，为贷款客户管理提供可渐进发展的蓝图。后续可按业务优先级拆解研发任务。
